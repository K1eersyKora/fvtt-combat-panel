# BG3队伍与剧情 0.2.3

0.2.3 修复剧情模式玩家右键平移闪跳：使用当前画布视角和按帧合并的单指针拖动。测距改为选择测距工具后按住左键、拖动原生 Foundry 尺实时显示、松开清除；Shift 保留原生自由测距。失焦、取消、切换工具和退出剧情均清理手势。三个态度按钮立即高亮当前选择，保存后继续由真实投票状态显示；一人一票和改票规则保持。入口 main-5.js。

依赖 `fvtt-combat-panel` >=0.15.2；在管理模组中同时启用两者。剧情开战同时需要 `fvtt-bg3-initiative` >=0.1.0 与 `fvtt-bg3-encounter-sfx` >=0.1.1。只启用父模块时仅保留底部战斗 HUD 和自动化。

0.2.2 跟随父模块的客户端性能档：低配采用真实骰值的轻量骰盘，完整模式继续使用 DSN 物理动画；已打开的骰盘在下次打开时采用新档位。队友卡改为事件驱动，缓存最近 16 张立绘的元数据；窄屏保留正文与资源列可读性。剧情投票、断线处理和先手请求由更新事件与明确倒计时驱动；检定观察标记按状态期限清理，不常驻 ticker。入口 main-4.js。

本模块提供队伍总览、自由／禁止／战斗移动、按玩家完全限制、BG3 属性及技能检定、剧情模式与一秒队友悬停卡。检定可选 Dice So Nice 5.2.4；剧情开战继续使用独立 `fvtt-bg3-encounter-sfx` 0.1.1。

队友档案的关键特性资源只显示中文，常用纯英文资源采用中文名称，无法识别的英文资源显示为“特性资源”。资源按行排列，剩余值、分隔符与上限使用固定宽度列，保持计数位置一致。

检定使用原生掷骰结果，在独立托盘内大范围翻滚约 1.5 秒，停稳后再显示结果并提交一次聊天卡。普通与优势／劣势都保留实际骰面；动画异常或提前关闭有有界兜底，不重复掷骰。

颜色、玻璃边缘、预设及 RGB 动态配色统一跟随父模块底部 HUD 的小齿轮设置，每位用户独立保存。子模块不保存第二套颜色。

原父模块队伍位置／缩放／显示、移动与限制、剧情状态、检定设置在首次启用时迁移，目标已有值时不覆盖。原始记录保留；角色权限不改动，单独移动例外和剧情投票／视野的文档 flag 沿用原存储路径。老的独立 BG3 检定模块仍启用时继续转接旧引擎，避免双弹窗／重复结算。

GM 入口：`game.modules.get('fvtt-party-tools').api.checks.open()`。原父模块 `api.checks.open()` 保留转接。

## 剧情开战与先下手为强

反对票过半后保留三秒改票时间；期末仍过半时先播放 BG3 入战音效，再自动将本场景剧情名单中的 PL、NPC 和敌人加入原生遭遇，掷先攻并开始第一轮，不额外暂停或等待四秒。非隐藏单位在剧情开启时记录，DM 选择的隐藏先手者可额外入战而保留其隐藏状态。

新增世界设置“剧情中允许先下手为强”，默认开启。PL 的态度栏旁有“先下手为强！”；DM 在剧情监视栏有相同按钮，先选中准备率先攻击的怪物／角色再点击。一次只开放一个先手者的原有 HUD，其他玩家保持剧情界面。取消准备不创建战斗；实际投出一次攻击（包括未命中）才退出全体剧情并进入战斗。资源由系统／Midi 原样处理，先手者不被置顶，仍按正常先攻行动。

接口：`api.story.firstStrike()`、`api.story.cancelFirstStrike()`；`api.story.state` 可读当前剧情和先手者。请求通过当前用户自己的 User flag 提交，由在线 activeGM 仲裁、验证 Token 权限并推进世界文档；不允许玩家直接创建遭遇。

安装、服务器部署与验证状态以项目 maintenance/party-tools/ 和 maintenance/bg3-initiative/ 的最新维护报告为准。
