# 3D 地图生成与排错


适用于 v0.15.16 随附的三维跑团 0.1.7 和方块建造 0.6.8。下文使用过往地图的实走结果说明常见故障。[工具安装和使用](3D-USAGE.md)

## 一、准备


**1. 标定原图。** 玩家图、GM 图和拆分楼层图要逐张标定，不要假设它们比例一致。

**2. 建两张表。**

- 区域表：记录每个区域的尺寸，并注明该尺寸来自哪张图，或是推断得出。
- 连接表：记录每条通路是双向还是单向，是否为秘密门、开关桥，哪些跨层移动合法，以及能否原路返回。

**3. 统一尺度。** 方块建造常用的约定是 5 尺主格、2.5 尺放置层、0.25 尺模型细节。项目里其他模板用过 1 尺阶梯高差，两套约定不可混用，开工前先确认当前模板用的是哪一套。

**4. 统一几何来源。** 人物占地、可行顶面、碰撞和模型必须来自同一份几何和同一个原点。后文多数“看着能走却走不通”的问题，根源都是这几样东西各算各的。

**5. 准备测试环境。** 使用独立测试世界，不要在正式战役里调试。

## 二、生成


**先草模，后纹理。** 用草模把主线和所有窄口走通，再处理纹理。窄口最容易暴露碰撞问题，提前发现的返工成本最低。

**材质（通用建议）：**

- 基色贴图按 sRGB 处理，法线和粗糙度贴图按线性处理。
- 重复平铺的表面要检查接缝处有无暗线。
- 转动相机和快速切图时，检查透明边缘和纹理异步加载的表现。

**像素风参数（项目实测案例）：** 色图 64×64，立牌 128 像素，采样用最近邻加 mipmap。这是该案例的取值，其他风格需另行确定。

## 三、回读


导出后，把交付的 GLB 重新读入并核对以下各项，不要只看建模软件里的样子：

- 用正俯视对齐玩家图核对单位、轴向和原点，再用关键剖面核对楼板厚度与上下方净空。
- 检查负缩放、镜像面、楼层节点、纹理相对路径和透明通道。换个目录重新载入实际交付件，检查漏掉的外部资源。

## 四、验收


**1. 通行**

- 主线和窄口由普通玩家实际点击并双向走通。记录实际拾取的顶面、预览脚底、移动后玩家与 GM 收到的 TokenDocument 坐标和标高，统一到同一坐标系再比对。
- 梯段接缝和楼盖处，分别测中心点和左右微偏的点，并对照剖面。
- 检查楼梯下净空和回程，确认最终脚底落在正确的层上。

**2. 门与桥**

- 门：站在同一个位置，依次测试关闭、打开、重新关闭，核对通行与视线。
- 桥：开启、关闭，并在桥上和桥下分别点击。
- 切换镜头检查遮挡。
- 由在线主 GM 代执行时，检查四点：两端坐标是否正确，桥上有占位时是否阻止关闭，是否出现错层，操作被拒绝时是否未扣费用。

**3. 视野与雾**

- 必须用真正的普通玩家账号验证，不能用 GM 视角代替。
- 检查亮区、灰雾、黑雾三种状态，以及墙后棋子和隐藏棋子是否正确不可见。
- 开关门后，确认门状态与视线缓存同步。
- 反复切换 2D 和 3D，确认渲染资源被释放。

**4. 性能**

分段计量，不要只报一个帧率：下载、解码、空间索引构建、首次可交互、移动渲染、路点等待。GM 和玩家分别记录，并使用同一机位，前后数据才可比较。

**5. 收尾与发布**

- GM 和玩家可用的素材可能不同，两种身份都要测。
- 验收结束后恢复原有棋子、门桥、资源和测试时改动的场景状态。
- 公开发布前移除账号信息、私有场景和 DM 注记，素材署名按实际许可处理。

## 五、项目实测案例


以下数据仅对所述地图和路径成立。

**洞窟岸路。** 一条 5 尺宽的岸路被默认 1.5 尺的辅助墙挤占，无法通行。按该图把辅助墙适配为 0.05 尺后，玩家双向走通。0.05 尺是针对这张图的取值，不是通用默认值。

**桥头与木台。** 从离格位置出发时，旧算法检索了 1944 个节点仍判定不通。另查出木台的走行高度为 30.19 尺，而实际模型为 30.7613 尺，两者不一致。修正精确端点和承重判定后，40 个光标点测试无误报。

**楼层误捡。** 在梯段接缝和 +45 尺楼盖处，点击可能误落到 +30 尺层。验收中的“中心与左右微偏”测试就是针对这个问题设的。

**视线与雾。** 案例中视线索引与原生结果对比 700 条射线，零差异；雾的对照用了 729 个像素。

**帧率。** 在一条特定的 GM 路径上，帧率从 29.1 提升到 39.4 FPS，P95 帧时间从 60.8 毫秒降到 52 毫秒。这只是该路径的结果，不能据此承诺所有地图的性能。

**施法后只剩特效。** 偶发现象，原因是共享的 WebGL 上下文被 PIXI 清屏。定位方法是固定机位逐帧检查。

**多地形 Tile 图。** 这类图历史上出现过玩家端异步加载得到空 mesh 的问题。无地形的训练场测试通过，不代表整图通过，必须用完整地图在玩家端验证。

## 六、问题与排查表


| 现象 | 可能原因 | 排查方法 | 依据 |
|---|---|---|---|
| 窄路看着够宽却走不通 | 辅助墙厚度挤占通道 | 查该图的辅助墙厚度，按图适配后双向实走 | 项目实测 |
| 桥头或平台判定不通，或光标误报 | 起点离格；走行高度与实模不符；端点或承重计算不准 | 对比走行高度与模型高度，核对端点和承重，多点点击验证 | 项目实测 |
| 点击楼梯或楼盖后落到错误楼层 | 接缝处误捡相邻层 | 测中心与左右微偏，看剖面、净空、回程和最终脚底 | 项目实测 |
| 棋子位置、碰撞与模型对不上 | 几何或原点不同源；模板尺度混用 | 确认占地、顶面、碰撞、模型同源同原点；确认未混用阶梯高差约定 | 通用建议 |
| 桥关不上或代执行结果异常 | 桥上有占位；两端坐标错误；错层 | 查占位阻止、两端坐标，确认拒绝时不扣费用 | 通用建议 |
| 平铺表面有暗线 | 贴图接缝或采样问题 | 检查重复平铺处，核对色彩空间设置 | 通用建议 |
| 透明边缘发白或纹理迟到 | 图像透明设置或异步加载 | 转相机、快速切图复现；回读 GLB 查图像透明 | 通用建议 |
| 导入后尺寸、朝向或位置不对 | 单位、轴、原点、负缩放错误 | 回读 GLB 逐项核对 | 通用建议 |
| 玩家看到墙后或隐藏棋子 | 视线缓存未与门同步；只用 GM 视角验过 | 用普通玩家账号验亮/灰/黑雾，开关门后复查 | 通用建议 |
| 切换 2D/3D 多次后变卡 | 渲染资源未释放 | 反复切换并观察资源占用 | 通用建议 |
| 施法后画面只剩特效 | 共享 WebGL 被 PIXI 清屏 | 固定机位逐帧定位 | 项目实测 |
| 玩家端地形缺失 | 多地形 Tile 图异步空 mesh | 用完整地图在玩家端测，不以训练场结果代替 | 项目实测（历史问题） |
| 帧率低但找不到原因 | 各阶段耗时混在一起 | 分段计量六个阶段，GM 与玩家同机位记录 | 通用建议 |
